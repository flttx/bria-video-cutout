## 2. 背景与目标

### 2.1 项目目标

操作者在 Windows 电脑的本地浏览器中选择视频，通过自动识别、文字描述或正负点指定前景，替换为预设纯色背景，预览并导出 MP4 文件，随后拷贝到 43 寸显示设备播放。

工具围绕“选择素材 → 指定目标 → 处理 → 检查结果 → 导出”组织操作。输入素材以 2K、4K 视频为主；输出尺寸、画面比例和帧率跟随原视频，不要求操作者选择导出分辨率档位。

43 寸目标设备为竖屏，画面比例 9:16。第一版保留原视频比例，界面提示“建议上传 9:16 竖屏视频，以适配目标设备”；该提示不作为强制比例校验，不自动裁剪、拉伸或补边为 9:16。设备原生像素尺寸另行确认，不能根据屏幕尺寸推断。

### 2.2 方案范围

本方案不包含自定义背景图片上传、其他 AI 模型接入、触屏专用 UI、公网多用户服务，以及超长素材自动分段后无缝抠图。43 寸是设备尺寸，不能据此推断屏幕原生分辨率或播放器兼容性。

## 4. 总体架构

### 4.1 组件职责

| 组件 | 技术与职责 |
| --- | --- |
| 本地浏览器前端 | React、TypeScript、Vite；负责素材选择、预览、标注、任务展示及下载 |
| 本地 API 服务 | Node.js、Fastify；负责校验、队列、直连或云端 Bria 适配、媒体处理调度和结果接口 |
| 轻量云端接口 | Cloudflare Workers Free；管理 Bria JSON 请求、内部鉴权与云端任务查询 |
| 云端任务记录 | D1 Free；保存上传引用、去重占位、请求标识与状态，不保存视频文件 |
| Bria Video API | 执行三种模式的 AI 处理；具体能力按第 6.2 节所列官方端点约束 |
| FFmpeg／FFprobe | 执行预处理、媒体探测、遮罩合成、转码和导出检查 |
| 本地文件存储 | 保存原素材、处理源片段、任务记录、可复用中间结果及成片 |
| 43 寸显示设备 | 接收导出文件，由设备播放器播放 |

### 4.2 数据流

```text
┌───────────────────┐
│ 本地浏览器前端    │ 选片、标注、预览、下载
└─────────┬─────────┘
          │ 本地 API
┌─────────▼─────────┐
│ 本地 API 与任务队列│ 校验、恢复、媒体处理调度
└─────┬────────┬────┘
      │        │
      │        └──────────► FFmpeg／FFprobe
      │                       预处理、合成、编码、校验
      ▼
┌───────────────────┐
│ Bria Video API    │ JSON 可经 Workers + D1；文件由本地直传
└─────────┬─────────┘
          │ 处理结果
          ▼
    本地文件存储 ─────► 导出 MP4 ─────► 43 寸设备播放
```

### 4.3 轻量云端接口（工程决策）

采用 Workers Free + D1 Free，为自用／内部 Demo 提供服务端接口。浏览器仍只访问本地 API；Node.js 向 Worker 申请上传授权、提交任务和查询状态，文件直接往返 Bria 文件服务。FFmpeg、FFprobe、源素材、Alpha／Mask 缓存和导出均留在本机。

云端不运行常驻队列、视频编码或后台轮询，不提供跨电脑历史同步。Node.js 关闭后 Bria 可继续处理；本地重新启动后查询原任务，及时下载有效结果。云端完成不能替代本地文件验收。

每次云端提交先在 D1 持久化唯一占位。同标识同参数复用，参数冲突拒绝；受理响应不明或受理后写库失败时不重新提交。查询使用 D1 条件更新限制同任务并发；首次明确拒绝后，仅用户主动恢复才生成新的提交尝试。

采用服务端 Bearer 密钥鉴权，Bria Token 存储于 Worker Secrets。签名上传地址和结果地址只返回受信任的本地 Node.js，不进入浏览器。保留 direct 模式兼容旧任务，切换只影响新任务；云端故障不自动回退直连。

**官方额度：**Workers Free 每日 10 万次请求、每请求 10ms CPU；D1 Free 每日 500 万行读取、10 万行写入，单库最大 500MB。视频不经过 Worker，也不存入 D1；账号额度内的 Cloudflare 免费不代表 Bria 免费。[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)、[D1 额度](https://developers.cloudflare.com/d1/platform/pricing/)、[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)。

**待实测：**真实部署的 CPU 用量、网络连通性、Bria 账号权限及费用；本地运行不能证明这些条件通过。

## 5. 业务流程

### 5.1 首次处理

1. **选择视频。**读取媒体信息，显示预览、尺寸、时长、帧率和音轨信息；文件不符合要求时给出明确原因。
2. **选择模式。**在自动识别、文字描述、点选目标中选择一种，页面即时显示对应限制。
3. **核验时长。**整段视频合规时隐藏裁选控件；超限时显示提示和裁选范围，只有片段满足限制才能提交。
4. **指定目标。**文字模式填写目标描述；点选模式暂停到同一帧，添加包含目标的正点及排除区域的负点。
5. **选择背景。**默认白色，可切换其他九种预设色；输出规格只读展示。
6. **开始处理。**本地服务完成校验与预处理，上传处理素材并调用 Bria，展示真实任务阶段。
7. **检查结果。**在“原视频／导出结果”页签中查看文件，重点检查目标完整性、边缘、运动连续性和音画同步。
8. **下载播放。**保存校验合格的 MP4，再拷贝到目标设备进行播放验收。

### 5.2 修改结果与重复导出

**工程决策：**结果设置变化后显示“待应用”，由操作者点击“应用修改并导出”发起处理，不在每次选择颜色时自动编码。

| 操作条件 | 处理方式 |
| --- | --- |
| 已缓存透明视频或遮罩 | 复用缓存，本地更换背景色并导出，无需再次调用 Bria |
| 只有有色 MP4，没有可复用缓存 | 阻止本地换色，说明需要重新抠图 |
| 设置与当前文件一致 | 突出下载入口，避免重复生成 |
| 需要更换识别目标或抠图模式 | 通过独立的“重新抠图”入口创建新处理任务 |
| 打开历史任务 | 列表展示缩略图、预览和下载入口；点击预览打开弹窗，展示已完成成品及实际规格；不载入历史参数，不替换当前原视频或导出结果 |
| 移除历史任务 | 已完成或失败且没有正在进行的处理／导出的任务可以移除；仅隐藏记录，保留本地视频，刷新后仍保持隐藏，并提供最近一次移除的撤销入口 |

移除记录不取消任务、不删除源视频或成品，也不清空当前工作区结果。对已移除任务重新发起本地导出或恢复处理时，记录重新显示，以便查看进度。

## 6. 功能设计

### 6.1 视频导入与预览

素材规格以 2K、4K 视频为主，具体宽高以读取到的原视频显示尺寸为准，不仅凭分辨率档位名称判断。第一版接受的画面比例跟随原视频，建议输入 9:16 竖屏素材；其他比例的合规视频可继续处理，成品保留其原有比例。文件大小、时长、容器和编码仍须满足下述接口限制。

**官方约束：**自动抠图接口列出的输入容器为 MP4、MOV、WebM、AVI、GIF，视频编码为 H.264、H.265、VP9、AV1、PhotoJPEG；上传服务只接收视频，单文件上限为 1 GB。容器和编码支持应按实际调用端点核验，不能仅凭扩展名判断可处理性。[S1：Remove Background](https://docs.bria.ai/video-editing/editing/remove-background)、[S4：Video Upload Service](https://docs.bria.ai/local-video-upload-service)。

**工程决策：**

- 上传后使用 FFprobe 检查真实容器、编码、时长、尺寸、帧率与音轨，拒绝损坏文件及不支持的输入；GIF 视频流作为动图特例识别。
- 浏览器无法直接播放受支持素材时，生成本地 H.264／AAC 兼容预览，支持播放和拖动。
- 兼容预览只用于交互，不替代处理源。自动模式使用预处理后的源片段，文字／点选模式使用专用处理代理，详见第 8 节。

### 6.2 三种抠图模式

| 模式 | 操作者输入 | 官方限制与返回内容 | 项目处理方式 |
| --- | --- | --- | --- |
| 自动识别前景 | 选择模式及背景色 | 最长 60 秒，输入最高 16000×16000；返回去背景视频，可选预设色或透明输出。[S1](https://docs.bria.ai/video-editing/editing/remove-background) | 选择透明缓存合成，或有色 MP4 直出 |
| 文字描述目标 | 输入需要保留的目标描述 | 最长 5 秒、最高 750p；返回遮罩视频。[S2](https://docs.bria.ai/video-editing/masking/mask-by-prompt) | 缓存遮罩，与源片段合成 |
| 点选目标 | 在同一帧添加正点／负点 | 最长 5 秒、最高 750p；按帧索引及坐标生成遮罩，正点包含、负点排除。[S3](https://docs.bria.ai/video-editing/masking/mask-by-key-points) | 映射坐标与帧索引，缓存遮罩并合成 |

**工程决策：**切换模式后重新核验时长并重置裁选范围，不静默截断素材；文字／点选显式使用 `auto_trim=false`，相关字段见 [S2](https://docs.bria.ai/video-editing/masking/mask-by-prompt) 和 [S3](https://docs.bria.ai/video-editing/masking/mask-by-key-points)。点选至少包含一个正点，所有点位于选中片段的同一帧，支持撤销和清空。

**待实测：**文字能否稳定区分多个相似目标、点选是否完整选中预期实例，以及发丝、遮挡和快速运动的分割质量。以上均不作为接口能力保证。

### 6.3 背景颜色

只提供以下十种纯色，不增加自定义图片或任意颜色输入。

| 颜色 | 本地色值 | 接口颜色名称 |
| --- | --- | --- |
| 白色（默认） | #FFFFFF | White |
| 黑色 | #000000 | Black |
| 灰色 | #808080 | Gray |
| 红色 | #FF0000 | Red |
| 绿色 | #00FF00 | Green |
| 蓝色 | #0000FF | Blue |
| 黄色 | #FFFF00 | Yellow |
| 青色 | #00FFFF | Cyan |
| 洋红 | #FF00FF | Magenta |
| 橙色 | #FFA500 | Orange |

**官方约束与工程决策：**Bria 的 `background_color` 接收预设英文名称，不接收 HEX；上表 HEX 用于本地色卡和 FFmpeg 合成。Bria 直出颜色与本地色值的精确一致性需要实测。[S1：颜色参数](https://docs.bria.ai/video-editing/editing/remove-background)。

### 6.4 导出规格

下表为**项目导出规范**，不是 Bria 的统一强制要求。

| 项目 | 规则 |
| --- | --- |
| 容器与编码 | MP4／H.264，非透明输出，采用 yuv420p 像素格式 |
| 尺寸与比例 | 第一版按原视频显示尺寸输出；2K 输入按原始尺寸输出，4K 输入按原始尺寸输出。保留横屏、竖屏、方形等原有比例，不统一转换为 9:16 或 16:9 |
| 旋转与像素比例 | 将旋转信息和像素宽高比归一化为实际显示尺寸 |
| 奇数尺寸 | 为兼容编码，宽或高为奇数时向上补最多 1 像素边缘 |
| 帧率 | 跟随源平均帧率归一化；不承诺逐帧保留可变帧率原始时间戳 |
| 音频 | 有源音轨则保留选中片段音频，无源音轨则保持无音频 |
| 手动规格 | 不提供分辨率选择；新任务和新导出使用源规格 |

**质量边界：**导出 4K 文件只表示文件尺寸，不表示文字／点选具备原生 4K 遮罩细节。放大遮罩不能恢复原本缺失的细节，这是图像处理推论；750p 约束来源为 [S2](https://docs.bria.ai/video-editing/masking/mask-by-prompt) 和 [S3](https://docs.bria.ai/video-editing/masking/mask-by-key-points)。

## 7. 页面与交互设计

### 7.1 工作台布局

外观参考 `3D_maker_web` 的工作台，采用单一工作面板，左侧参数、右侧上传与预览，用分割线组织区域。

| 区域 | 内容与交互 |
| --- | --- |
| 左侧参数区 | 顶部显示 43 寸目标设备信息，其下放置模式、目标设置、十色色卡及主操作 |
| 右侧预览区 | 上传入口与“原视频／导出结果”页签；原视频下集中播放、文件信息及必要的裁选控件 |
| 任务信息区 | 每条记录直接展示缩略图、文件名、模式、原视频时长、处理片段时长、背景色和创建时间，右侧排列状态与预览、下载、移除按钮；不折叠单条记录，窄屏时操作换行。处理步骤、进度、失败原因及恢复入口集中在对应记录；完成任务不再显示进度条。视频在独立弹窗播放，关闭后停止播放并恢复焦点；不提供载入参数功能 |
| 完成态 | 收起新任务模式和缓存设置，显示当前文件规格、待应用状态、下载及重新抠图入口 |

### 7.2 视觉与可访问性

**工程决策：**

- 进行中任务的四个步骤以连续连线连接，区分已完成、当前和待处理阶段；窄屏保持步骤与连线连续。
- 使用中性暗底、品牌橙和独立深色预览底；主按钮颜色满足白字对比度要求，主题色不改变导出背景色。
- 字体采用 Outfit 与中文系统字体回退；正文 14px、辅助文字 12px，以 4px 为间距基数。网络字体不可用时仍可阅读与操作。
- 840px 以下按相同 DOM 顺序上下排列，避免窄屏横向溢出；未选文件时隐藏空播放和裁选控件。
- 模式限制随选择即时更新；代理处理说明和缓存选项放入可展开区域，页面不放官方文档链接。
- 目标设备标注“43 寸竖屏设备 · 9:16”，在设备说明或上传区提示“建议上传 9:16 竖屏视频，以适配目标设备”；非 9:16 素材仅作适配提示，不因比例阻止提交。
- 色卡保留颜色名称、无障碍名称和选中态；可交互控件提供可见键盘焦点，页签支持键盘切换。

前端主题和布局在本项目内独立维护，不依赖参考项目的运行或构建，也不因外观对齐而引入其他设备预设。

### 7.3 环境与平台关系

**工程决策：**运行环境为 Windows、Node.js 22.12+、npm 和可用的 FFmpeg／FFprobe。前端与 API 仅面向本机访问，API 监听回环地址；不作为公网多用户服务部署。

未来由 `3D_maker_web` 增加独立入口。**待确认：**入口位置、打开方式、身份认证及部署关系；本方案不依赖这些集成条件才能本地运行。

## 8. 视频处理策略

### 8.1 预处理与目标映射

**工程决策：**先按选定范围生成源片段，归一化旋转、像素比例和帧率。文字／点选另生成保持比例、尺寸不超过 1280×720 的处理代理；这是项目选择，不是 Bria 规定的代理尺寸。

点选在前端保存归一化坐标和源视频时间，提交时换算为代理视频像素坐标，并根据片段起点和代理帧率换算帧索引。坐标和时间映射必须通过裁选、缩放、竖屏和旋转素材验证。官方点选字段及像素坐标示例见 [S3：Mask by Key Points](https://docs.bria.ai/video-editing/masking/mask-by-key-points)。

本地最多 100 个点、文字最多 2000 字符等保护阈值属于工程限制，不应标为官方规则。

### 8.2 按结果类型分流

| 路径 | 使用条件 | 执行方式 | 换色能力 |
| --- | --- | --- | --- |
| 自动模式透明缓存 | 默认开启可复用结果 | 请求透明视频，缓存后本地合成所选纯色 | 可复用缓存换色 |
| 自动模式有色直出 | 关闭可复用缓存 | 请求所选预设色 MP4；规格和音轨合格时直接保存 | 无透明缓存时需重新抠图 |
| 文字／点选遮罩合成 | 返回遮罩视频 | 下载并缓存遮罩，与源片段配准后合成 | 可复用遮罩换色 |
| 规格修正 | 结果不符合项目导出要求 | 本地转码、补边或恢复源音轨后重新校验 | 取决于是否保留透明／遮罩缓存 |

**官方参数与工程选型：**自动模式显式设置 `auto_zoom=false`、`preserve_audio=true`；透明路径选择 `Transparent` 与 `webm_vp9`，有色路径选择颜色名称与 `mp4_h264`。透明背景搭配不支持 Alpha 的编码会回退黑底并产生警告，服务端必须检查结果警告，不能把黑底视频当作透明缓存。[S1：输出与透明度规则](https://docs.bria.ai/video-editing/editing/remove-background)。

项目不依赖自动背景默认值：官方文档说明段与参数表的默认颜色存在差异，因此始终显式传值。[S1：Remove Background](https://docs.bria.ai/video-editing/editing/remove-background)。

**工程决策：**遮罩与源片段按帧序号统一时间基准，并检查比例、帧率和帧数；使用 FFmpeg 完成遮罩缩放、Alpha 合并和纯色合成，再加入源音轨。工具能力见 [S8：FFmpeg Filters](https://ffmpeg.org/ffmpeg-filters.html)。能直接交付合格有色 MP4 时，不额外运行合成编码。

### 8.3 异步任务与恢复

**官方协议：**Bria 提交后返回 HTTP 202、`request_id` 和 `status_url`；视频任务建议约每 5 秒查询，结果地址具有时效，完成后应及时下载，不因仍在处理而重复 POST。[S5：异步请求与轮询](https://docs.bria.ai/getting-started/async-requests)。

**工程决策：**本地采用轮询和串行任务队列，不依赖公网 Webhook。任务阶段为：

**排队 → 准备素材 → 上传 → 提交 → 处理 → 下载 → 导出 → 完成／失败。**

- 使用客户端请求 UUID 去重；同一标识、相同参数复用任务，参数冲突返回明确错误。
- 原子保存任务记录，服务重启后恢复已有任务，避免重新创建付费请求；浏览器刷新只读取历史记录，默认进入原视频上传入口，不自动选中历史任务或成品。
- 任务卡片中的步骤按真实阶段更新，未返回百分比的处理阶段使用不定进度条；上传素材阶段显示浏览器上报的百分比。本地换色导出单独标注本地处理状态，失败时保留上一次成功成品的预览和下载入口。缺少旧素材记录时明确提示文件名或原视频时长未记录，不根据片段时长猜测原视频规格。
- 已有上游请求标识时，只恢复原任务查询或下载；提交结果不明时阻止自动重发，要求核对上游任务。
- 临时查询错误采用有限退避重试；查询超时不等于 Bria 任务失败，也不自动触发重新抠图。
- 浏览器任务列表只在首次连接、重连、手动刷新及必要的列表操作后读取；进行中任务按 ID 查询，本地导出按导出 ID 查询，共用一个轮询循环，一轮完成后等待 2 秒，完成／失败后停止。页面隐藏时暂停后续状态查询，返回后继续，不影响服务端任务执行。
- 浏览器健康检查由页面顶部状态与提交控件共享，在线且抠图就绪时每 60 秒、本地离线或云端抠图不可用时每 15 秒检查；页面隐藏时暂停后续检查，返回后按上次检查时间恢复。浏览器查询本地服务与服务端查询 Bria 是两个独立生命周期。
- 只有文件落盘并通过导出检查后才标记完成；界面展示真实阶段，不伪造进度百分比。

### 8.4 导出检查与数据保存

**工程决策：**利用 [S9：FFprobe](https://ffmpeg.org/ffprobe.html) 检查真实尺寸、编码、像素格式、帧率、时长、完整帧数和音轨。检查失败时保留明确错误，不将未完成文件开放为可下载成片。

原素材、本地任务及结果保存在项目本地数据目录。云端模式另在 D1 保存 Bria 任务与去重记录，D1 不承担视频备份或本机历史同步。为保留任务恢复和换色能力，不自动清理缓存；确认不再使用且服务停止后再手动清理。导出前需要考虑源视频、代理、Alpha／Mask 与成片同时占用的磁盘空间。

## 9. 安全、异常与成本控制

### 9.1 凭据与数据保护

**官方安全要求：**Token 放在服务端环境变量或密钥管理中，通过 `api_token` 请求头调用，不能内嵌到客户端。[S6：Authentication](https://docs.bria.ai/getting-started/authentication)。

**官方上传规则：**`upload_url` 有效期为 1 小时，`file_url` 为 1 天；持有地址即可访问相关资源，应视为秘密。[S4：Video Upload Service](https://docs.bria.ai/local-video-upload-service)。

**工程决策：**前端及日志不包含 Token、预签名 URL、完整上游响应或私有磁盘路径。浏览器只获取本地业务标识、必要元数据、脱敏错误和本地文件接口；后端限制本地来源与文件访问范围。

### 9.2 异常处理

| 异常 | 处理原则（工程决策） |
| --- | --- |
| 输入损坏、格式不支持或片段超限 | 提交前拦截，提示更换文件或调整片段 |
| 凭据无效、套餐权限不足 | 明确提示配置或权益问题，不反复提交 |
| 限流或临时查询网络错误 | 对查询执行有限退避，保留已有任务标识 |
| 创建请求的结果不明 | 标记需核对，不自动重发付费请求 |
| 中间结果过期、下载失败 | 尝试恢复已有任务可用结果；无法恢复时说明原因 |
| 合成失败或磁盘不足 | 报告本地失败，保留可复用缓存，不标记成功 |
| 尚未实现的能力 | 返回明确不支持错误，不生成占位完成结果 |

Bria 的鉴权、权限、限流及处理错误以具体端点和 [S7：Rate limits and errors](https://docs.bria.ai/getting-started/rate-limits-and-errors) 为准；状态查询也计入限流，不能把所有错误都归为“重试即可”。

### 9.3 成本与性能

**工程决策：**通过提交前校验、请求去重、串行队列和中间结果复用减少无效处理。自动模式默认保留透明缓存，文字／点选保留遮罩，重复换色仅消耗本地计算资源。

不承诺固定单次费用、处理秒数或最大本地吞吐量。账号费用与可用额度按实际套餐核对；4K 素材的内存、磁盘与编码耗时需在目标电脑上测量。

云端存储失败或免费额度耗尽时返回明确错误，不自动升级套餐。D1 去重记录不自动清理，按主键查询避免全表扫描；在控制台观察请求、CPU 和 D1 行数与存储。

## 10. 验收标准

本节定义验收方法和通过条件，不表示已经完成验收。

| 验收维度 | 主要范围 | 通过条件 |
| --- | --- | --- |
| 功能闭环 | 导入、三种模式、裁选、十色、预览、下载 | 每种模式能生成真实可播放文件，输入不合法时明确拦截 |
| 任务可靠性 | 重复点击、刷新、重启、网络失败、提交结果不明 | 可恢复原任务；不因重试而重复创建付费任务 |
| 本地换色 | Alpha／Mask 复用、有色直出限制 | 有缓存可本地换色；无缓存明确说明重新抠图要求 |
| 文件规格 | 横屏、竖屏、方形、旋转、奇数尺寸、音轨 | 符合第 6.4 节规则，规格显示与实际文件一致，帧数和音画同步正确 |
| 格式与预览 | 支持的容器／编码，浏览器兼容预览 | 可以播放、拖动和标注；预览不改变处理源和导出目标 |
| 画面质量 | 发丝、细小边缘、多实例、遮挡、快速运动 | 用代表性素材确认目标完整性和时序稳定性，由用户确认可接受效果 |
| 界面与可访问性 | 桌面／窄屏、焦点、页签、状态和错误提示 | 无关键遮挡或横向溢出，控件可辨识，操作反馈与实际状态一致 |
| 安全 | 客户端响应、日志、来源限制和文件访问 | 无凭据、签名地址或私有路径泄露，不可越界访问本地文件 |
| 性能与设备 | 长片、4K 源素材、磁盘占用、43 寸播放器 | 实测资源消耗可接受；设备上完整播放，无解码失败和明显音画异常 |

验收证据分开记录：静态检查与自动化测试、真实 API 联调、真实文件检查、浏览器操作、用户视觉确认、设备实机播放。短片链路通过不能替代复杂视频质量验收；电脑浏览器播放通过不能替代设备验收。

### 11.1 视频画面裁剪工具初步调研方案

**候选方案：**优先评估 `react-easy-crop`，参考其[官方视频裁剪示例](https://valentinh.github.io/react-easy-crop/docs/examples/video)。用于帮助操作者把非 9:16 素材调整为竖屏画面；这里的裁剪指画面区域和宽高比调整，与现有按开始、结束时间裁选处理片段的功能分开。

#### 11.1.1 组件能力与边界

| 项目 | 初步判断 |
| --- | --- |
| 交互能力 | 支持视频、拖动和缩放，可通过 `aspect` 指定裁剪框比例，拟设置为 `9 / 16` |
| 裁剪参数 | `onCropComplete` 提供百分比区域和像素区域，可用于保存选区及传递裁剪参数 |
| 格式边界 | 预览依赖浏览器 HTML5 视频支持，不能把组件支持范围等同于 Bria 输入格式范围 |
| 职责边界 | 可复用其选区交互；视频文件的实际裁剪、编码与下载仍由本项目实现 |
| 授权 | 仓库采用 MIT 许可证；集成时保留对应版权及许可声明 |

组件能力依据[官方仓库说明与 API](https://github.com/ValentinH/react-easy-crop#props)，授权依据[许可证原文](https://github.com/ValentinH/react-easy-crop/blob/main/LICENSE)。官方视频示例提供交互参考，不构成本项目 2K／4K 性能或完整导出链路的验收证据。

#### 11.1.2 拟接入方式

**工程建议，待原型验证：**采用“React 前端选择画面区域 + 本地 FFmpeg 裁剪编码”，复用现有媒体处理能力。FFmpeg 的 `crop` 滤镜支持按宽、高和左上角坐标裁剪视频，见[官方 crop 文档](https://ffmpeg.org/ffmpeg-filters.html#crop)。

1. **选择素材。**保留原始文件；浏览器不能直接播放时使用兼容预览，预览与原视频采用一致的旋转方向、画面比例及时间基准。
2. **调整画面。**提供可选的 9:16 裁剪步骤，支持拖动、缩放、重置和播放检查；初步限定为全片固定裁剪区域，不包含逐帧跟踪或动态运镜。
3. **确认并生成。**将预览选区映射到旋转和像素比例归一化后的原视频坐标，由服务端校验边界、比例和编码所需的偶数尺寸，再交给 FFmpeg 处理。不能直接把低分辨率预览的像素坐标用于 2K／4K 原片。
4. **进入抠图。**先生成独立裁剪文件，再以该文件作为新的输入源进入自动识别、文字描述或点选流程。裁剪应在点位标注之前完成，避免源画面变化后复用旧点位；原始文件保留，可重新选择。

未启用裁剪时仍按原视频尺寸和比例输出；启用后，以裁剪文件的实际尺寸作为后续导出依据，不为保留“2K／4K”档位名称而自动放大画面。最终裁剪尺寸、音轨及帧率规则在原型验证后确定。

#### 11.1.3 验证范围与接入条件

| 验证项 | 通过条件 |
| --- | --- |
| 交互与性能 | 代表性 2K／4K 素材可预览、定位和调整选区；记录耗时及内存占用，确认目标电脑上可用 |
| 坐标与比例 | 横屏、竖屏、旋转元数据、非方形像素及兼容预览的选区与实际导出一致；9:16 及偶数尺寸取整不产生可见偏移 |
| 视频质量 | 裁剪文件可播放，音轨与时间片段对应、音画同步；明确沿用源平均帧率规则及可变帧率边界 |
| 操作衔接 | 取消或重置不改原文件；裁剪文件可进入三种抠图模式，点位基于新的源画面建立 |
| 工程适配 | 核对 React／TypeScript 兼容性、依赖与许可，验证桌面/窄屏布局和键盘操作 |

第一版继续提示使用 9:16 素材，按原视频规格导出。`react-easy-crop` 作为后续裁剪功能的优先候选，完成上述验证后再确定接入；当前方案不代表组件已经集成或裁剪导出已经实现。

## 13. 方案结论

本方案将 Bria Video API 用于三种视频抠图模式，将 FFmpeg／FFprobe 用于确定性的视频处理与文件验收。导出文件跟随源视频规格，背景限于十种预设纯色；可复用的透明视频或遮罩支持本地换色，异步任务可恢复且不会因状态不明而自动重复提交。设备兼容性与复杂素材抠图质量按第 10 节和第 11 节的验收及待确认条件另行验证。
