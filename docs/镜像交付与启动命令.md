## 2. 腾讯云服务器启动

服务器先装好 Docker Engine 和 Compose 插件，将交付目录上传至 `/opt/bria-cutout` 等目录，然后执行：

```bash
cd /opt/bria-cutout
sha256sum -c SHA256SUMS
docker load -i images.tar
docker compose up -d
docker compose ps
```

`api` 显示 `healthy` 即服务就绪。只有一个 API 容器，不需要 `sh start.sh`、额外 Token 文件或证书文件。Compose 只使用导入的本地镜像，不在服务器构建或拉取应用镜像。

## 3. 没有域名时验证接口

默认仅监听服务器 `127.0.0.1:3001`，不提供网页首页。在自己的电脑执行以下命令并保持终端打开，替换 SSH 用户和服务器 IP：

```bash
ssh -N -L 3001:127.0.0.1:3001 用户名@服务器IP
```

在自己的电脑另开终端验证接口，curl 会提示输入 `PRIVATE_ACCESS.txt` 中的密码：

```bash
curl -u admin http://localhost:3001/api/health
```

Windows PowerShell 用 `curl.exe -u admin http://localhost:3001/api/health`。正确响应包括 `ok: true`、`tokenConfigured: true` 和 `processingReady: true`。这些状态仅说明本地服务和配置就绪，不代表已验证 Bria 的外部网络或额度。

本机运行镜像时直接访问上述 API 地址，无需 SSH。APP 真机不能通过自己的 localhost 访问电脑；正式真机接入需要可访问的服务端 HTTPS 地址。

## 4. 独立网页如何接入

### 当前仓库网页：已配置自动认证

本机已创建 `apps/web/.env.server.local` 并填入本次交付包的接口凭据。Docker Desktop 中的 API 启动后，在仓库根目录直接运行 `npm run dev`，打开 **http://localhost:8080** 即可，无需登录或额外选择模式。网页启动进程读取以下配置，代理 `/api` 并自动附加认证，上传/预览/下载均使用该代理；这些值不进入浏览器脚本。

```dotenv
CUTOUT_API_BASE_URL=http://127.0.0.1:3001
CUTOUT_API_USERNAME=admin
CUTOUT_API_PASSWORD=填写PRIVATE_ACCESS.txt中的Password
```

上述文件已被 Git 忽略；其他机器可以从 `apps/web/server-config.template` 复制创建。修改配置后重启前端；不要加 VITE_ 前缀。网页地址必须与 API 的 WEB_ORIGIN 一致，本次默认是 `http://localhost:8080`。如果 API 在远端，用 SSH 将其回环 3001 转发到本机，或将 BASE_URL 改成它的 HTTPS 地址。

`npm run dev` 只启动前端，不负责启动 Docker API。网页现在请求同源 `/bria-cutout/api/...`；直连原镜像时由 Vite 去掉 `/bria-cutout`，接入公司网关时配置 `CUTOUT_API_PATH_PREFIX=/bria-cutout` 以保留前缀。发布为静态网页后，Vite 代理不会随静态文件发布，正式网页的托管服务需另外配置同源 `/bria-cutout/api/` 转发和认证。

### 其他独立网页

API 使用 HTTP Basic 自动认证，用户名 `admin`，密码见私有交付文件。独立网页从自己的启动配置读取凭据，每个请求自动带 Authorization，无需用户输入账号。本版是单人私有服务，不提供注册、多用户或角色权限。

网页服务器可用环境变量 `CUTOUT_API_BASE_URL`、`CUTOUT_API_USERNAME`、`CUTOUT_API_PASSWORD` 保存接入配置。如果网页有自己的后端代理，可由代理读取这些变量并附加认证头；如果是纯静态网页，需要由网页启动流程将变量注入运行配置，例如 window.APP_CONFIG。浏览器不能直接读取服务器环境变量；注入到浏览器的接口凭据不再保密。这里只交付 API，网页的配置注入由独立网页项目实现。

`compose.yaml` 的 `WEB_ORIGIN` 是**网页所在的来源地址**，不是 API 地址。默认允许 `http://localhost:8080`；例如网页部署在 `https://web.example.com`，修改为：

```yaml
environment:
  WEB_ORIGIN: https://web.example.com
```

地址包含协议、主机和实际端口，末尾无 `/`，只允许一个精确来源，不使用 `*`。修改后运行 `docker compose up -d`。公网网页来源要求 HTTPS，本地调试允许 localhost/127.0.0.1/IPv6 回环 HTTP。

网页直接调用示例（运行配置由独立网页的启动流程注入，里面不含 Bria Token）：

```javascript
const { apiBase, apiUsername, apiPassword } = window.APP_CONFIG;
const authorization = 'Basic ' + btoa(apiUsername + ':' + apiPassword);
const response = await fetch(apiBase + '/api/health', {
  headers: { Authorization: authorization },
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const health = await response.json();
```

浏览器自动发送 Origin 和跨域预检。服务端允许配置的来源以及所需认证、上传和 Range 请求头。JSON 写入请求还需 `Content-Type: application/json` 与 `X-Cutout-Client: 1`；二进制上传用 `application/octet-stream`、`X-Video-Filename: encodeURIComponent(file.name)` 和同样的客户端标记。

下载和预览也要求认证。网页应通过带 Authorization 的 fetch 读取 Blob，再创建本地 Blob URL 播放/下载；不能把账号密码拼进 URL。接口返回的 `/api/...` 相对路径应相对 `apiBase` 解析，而不是网页域名。跨域响应已暴露 Content-Disposition、Content-Length、Content-Range 和 Accept-Ranges。

## 5. APP 如何接入

APP 使用同一组 `/api/*` 接口和 Basic 认证。原生 HTTP 客户端通常不发送 Origin，不受浏览器 CORS 限制；仍须提供账号密码，POST 仍须带 `X-Cutout-Client: 1`。如果是 WebView，则按网页的 Origin/CORS 规则接入。

按用户选择，APP 将接口账号密码作为接入配置随包提供，网络层统一附加 Authorization，用户无需登录。该共享凭据可从安装包或运行环境中提取，需要轮换时更新客户端配置。视频播放器或下载器需要支持附加 Authorization 请求头，或者先下载到 APP 私有文件再播放。正式远程调用使用 HTTPS。

常用接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/health`、`GET /api/config` | 健康状态、处理参数 |
| `POST /api/videos` | 上传原始视频字节 |
| `POST /api/videos/:id/preview` | 生成预览 |
| `GET /api/videos/:id/preview` | 读取预览，支持 Range |
| `POST /api/jobs`、`GET /api/jobs/:id` | 创建及查询任务 |
| `GET /api/jobs` | 历史任务 |
| `POST /api/jobs/:id/resume` | 恢复任务 |
| `POST /api/jobs/:id/export` | 用缓存结果重新导出 |

任务参数结构参考仓库 `docs/API_CONTRACT.md` 和 `apps/api/src/model.ts`。提交抠图可能产生 Bria 费用；本交付的自动验证不提交真实收费任务。不要对结果不明的提交自动重试。

## 6. 以后绑定 API 域名

由服务器已有入口将 API 域名反向代理到 `127.0.0.1:3001`，保留 Authorization、Origin、Range 及 X-Cutout-* 请求头；客户端将 `apiBase` 改为该 HTTPS 地址。WEB_ORIGIN 仍填写网页来源，APP 原生调用无需修改它。API 镜像无需重建。

域名、证书和外部入口本次不配置。代理应允许 1 GB 上传、600 秒读写超时，并关闭请求/响应缓冲。默认 API 端口不直接暴露公网；无域名阶段用 SSH 隧道测试。

## 7. 日常命令和数据

在交付目录执行：

```bash
docker compose ps
docker compose logs --tail=100 api
docker compose restart api
docker compose stop
docker compose up -d
```

素材、任务和成片保存在命名卷 `bria-cutout-server_media`，停止/重建容器保留数据。不要执行 `docker compose down -v`，它会删除数据卷。任务被服务器接收后可后台处理，不要求网页或 APP 一直在线。更新前等待任务完成，再停止服务并备份数据卷；磁盘需监控，本版不自动清理素材。

## 8. 本地重新构建

在 Windows 本地仓库根目录运行，Docker Desktop 使用 Linux 引擎：

```powershell
powershell -ExecutionPolicy Bypass -File deploy/standalone/build-release.ps1 -Tag backend-20261028-v2
```

默认 `linux/amd64`，ARM 服务器追加 `-Platform linux/arm64`。默认按本地 API 的环境优先级读取 Bria/Tripo 配置，或通过 `-TokenFile` 指定独立的私有配置文件。版本号不能重复。

每次构建生成新的 API 访问密码。Bria Token 或接口密码更新后需重新构建/导入，替换 Compose 和 PRIVATE_ACCESS.txt，并同步更新 APP/网页配置。保留同一 Compose 项目名及数据卷。构建从不推送镜像。

验证记录见仓库 `docs/PROGRESS.md`；本地镜像验证不代替腾讯云网络、真实 Bria 任务、长片性能和设备验收。
